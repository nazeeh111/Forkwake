# One cut. Two ledgers.

This record follows the existing [JavaScript transfer](../../examples/javascript/workflow.js), not a live payment provider. It was run from source commit `86e3c18f343a6aeac3d2e75ff38225b9b644e8c8` (tree `0e9380ef8d83782e291228c15df319d2c0a98afe`) with Node 24.14.0 and locked Binaryen 132.0.0. The documented requirement remains Node 20 or newer; this capture does not verify every supported Node release.

## Run the same branches

From the repository root, after `npm ci --ignore-scripts`:

```sh
node cli.mjs capture --script examples/javascript/workflow.js --out first-cut
node cli.mjs continue --workspace first-cut/workspace.forkwake \
  --responses 1 --out reserved-cut
node cli.mjs continue --workspace reserved-cut/workspace.forkwake \
  --responses 1,1 --out approved-ending
node cli.mjs continue --workspace reserved-cut/workspace.forkwake \
  --responses -1,-1,1 --out timeout-ending
```

Every output directory must be new. Each process imports the portable cut independently. The shared cut has already answered **Reserve funds** with `1`. It pauses at **Confirm transfer** with `amount: 25`, `phase: reserved`; the account balance is now `75`.

- Approval: **Confirm transfer → 1**, **Publish receipt → 1**. Emitted balance `75`, recipient `45`, conserved `true`; `resultI32 = 0`.
- Timeouts: **Confirm transfer → -1**, **Retry confirmation → -1**, **Publish receipt → 1**. Emitted balance `75`, recipient `20`, conserved `false`; `resultI32 = 1`.

The final `1` in each sequence answers the receipt decision; it is not another transfer approval. The faulty policy treats a second timeout as settlement without crediting the recipient. This is a manual witness, not an exhaustive search or a minimum claim. The corrected source is [separate](../../examples/javascript/corrected.js).

## Inspect the evidence

[Paired record](paired-outcomes.json) binds the script SHA-256, shared workspace hash, actual reports, replies, output and import semantics. Unabridged CLI outcomes: [reserved cut](reserved-cut.json), [approval](approved-outcome.json), [timeouts](timeouts-outcome.json). These contain synthetic source/guest metadata. The approximately 8.7 MB portable workspace itself is regenerated by the commands above rather than included as an opaque binary artifact. The pinned digest identifies the recorded artifact. Fresh exports can differ because each session reseals independently; compare source, retained state and outcomes. Other runtime versions may also change exported bytes.

The report records `importReexecutedDecisions: 1` and `branchPrefixReexecuted: false` for both endings. Import verifies the earlier execution once, then each branch resumes the saved continuation. Both endings pass the workflow's self-cycle and Map-key identity checks; the closure and Promise steps are part of that same executed program. This does not establish general executor correctness.

In the interface, run `npm start`, open `/futures`, choose **Reopen a saved cut**, and select `reserved-cut/workspace.forkwake`. Advance the replies above, select the first tree node to return to the shared cut, then create the other ending. The [workbench capture](workbench-current.png) is this actual route.
